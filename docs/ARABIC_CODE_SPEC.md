# زيتونة (Zaytuna) — مواصفة المنتج والتصميم
## لغة برمجة عربية + مصحّح أكواد تلقائي متعدد اللغات + حارس Unicode

**التاريخ:** أكتوبر 2026 · **السوق:** عالمي (عربي أولًا) · **الجهاز:** موبايل أولًا (iOS + Android) ثم سطح المكتب
**حالة النموذج:** عامل فعليًا — 67 اختبارًا ناجحًا، وكل المخرجات في هذه الوثيقة حقيقية (انظر `DEMO_TRANSCRIPT.md`).

## 0) الفكرة في ستة أسطر

1. **المشكلة 1:** المطوّر العربي يكتب بالإنجليزية يوميًا — وأخطاء «اللغة» (رقم عربي في عدد، فاصلة عربية `،` بدل `,`، حرف اتجاه مخفي) تُنتج أخطاءً غامضة يشرحها المترجم بالإنجليزية.
2. **المشكلة 2 (2026):** الكود المولَّد بالذكاء الاصطناعي أكثر من **42%** من الكود، **96%** من المطوّرين لا يثقون به، وبطء المراجعة انفجر (**+441%** زمن المراجعة في أعلى الفرق استخدامًا للـ AI).
3. **المنتج:** (أ) **مصحّح تلقائي** يفهم أخطاء العربية داخل أي كود ويصلحها بعد التحقق، (ب) **تشخيص عربي** لكل لغة مدعومة، (ج) **لغة برمجة عربية «زيتونة»** تُترجم إلى جافاسكربت — عربية الوجه، جاهزة النظام.
4. **التميّز:** لا يوجد اليوم أي أداة تجمع الثلاثة. التصحيح الحالي للسوق إمّا بوت مراجعة بالإنجليزية على الويب (Gitar/Snyk/Musely)، أو لغة عربية ميتة بلا أدوات (قلب 2012 — آخر تحديث يناير 2013).
5. **قاعدة التصميم:** اللغة **جسر لا جزيرة** — كل سطر عربي يُترجم حتمًا 1:1 إلى جافاسكربت، ويوجد دائمًا مخرج (لا قفل)، فالمستودعات والمكتبات والمترجمون كلها تعمل كما هي.
6. **القاعدة الذهبية للمصحّح:** **لا يُكتب أي إصلاح قبل اجتيازه مدقّق اللغة الحقيقي** (node --check / py_compile / مترجم زيتونة). إن فشل الإصلاح — نقول ذلك ولا نكتب شيئًا.

## 1) لماذا لم ينجح «قلب»؟ (الدرس الذي بنينا عليه)

| الحقيقة | التفصيل |
|---|---|
| **قلب (Qalb/قلب)** — رمزي ناصر، 2012، Eyebeam نيويورك | أول لغة برمجة عربية حقيقية: نمط Scheme، كلمات لبنانية («قول» بدل «قل»)، `؟` للمنطق، أرقام هندية (١٠)، تخطيط RTL كامل |
| **التقنية** | مفسّر شجري بجافاسكربت (Peg.js + jq-console)، MIT، تعمل في المتصفح |
| **النهاية** | **آخر تحديث: يناير 2013 — مهجورة منذ 13 سنة** |
| **اعتراف صاحبها** | «لإنشاء تجربة برمجة عربية كاملة تحتاج إعادة كتابة 40 سنة من هندسة البرمجيات بالعربية — وهذا مستحيل». وكل نظام تتعامل معه اللغة إنجليزي. |
| **قبله** | AMMORIA وغيرها: كلمات عربية كواجهة على أدوات إنجليزية — «جهد محكوم بالفشل» بحسب ناصر نفسه |

### ما نفعله مختلفًا (ثلاث نقاط حاسمة)

1. **جسر لا جزيرة:** قلب حاولت أن تكون *كل شيء* (مفسّر + محرر + عالم). زيتونة **تترجم إلى جافاسكربت** — فـ npm و TypeScript والمتصفح والمترجمون يعملون فورًا، ولا يوجد «جدار» عند حدود اللغة.
2. **الحل ليس اللغة فقط — بل الألم:** قلب لم تجب على سؤال «لماذا أتعلم لغة عربية؟». زيتونة تجيب بفائدتين فوريتين حتى لو لم يكتب المستخدم سطرًا واحدًا بلغتها: **مصحّح الأخطاء العربية** و**التشخيص العربي** لأكواد جافاسكربت/بايثون الموجودة عنده.
3. **2026 غير 2012:** اليوم توجد نماذج لغوية تفهم الكود وتشرحه وتصلحه. اللغة الصغيرة لا تحتاج 40 سنة من المكتبات — تحتاج **واجهة عربية فوق نظام جاهز** (وهو ما تفعله زيتونة حرفيًا).

## 2) الحقيقة التقنية المثيرة: العربية مدعومة أصلًا (وإن لم يعرفها أحد)

تحقّقنا من ذلك عمليًا في بيئة التشغيل (Node 22.22.3 / Python 3.11.2):

```text
Python: المجموع · عدد_الطلاب · قيمة   → أسماء صحيحة (بعد NFKC) ✅
JavaScript: let المجموع = 5            → يقبلها ✅
JavaScript: let متغير١ = 7             → يقبلها (الرقم الهندي داخل الاسم) ✅
JavaScript: let س = ٥;                 → ✖ SyntaxError: Invalid or unexpected token
Python:     س = ٥                      → ✖ SyntaxError: invalid character '٥'
JS: let ي = 1; let ى = 2;              → كلاهما صحيح! (خطر خلط بصري) ⚠
```

**الاستنتاجات الثلاثة التي بنيت عليها المواصفة:**

1. «أسماء عربية في الكود» **مسألة واقع اليوم** لا مستقبل — لكن أحدًا لا يبني أدوات لها. هذه أول فجوة منتج.
2. **الأرقام العربية في الأعداد تنتج أخطاءً حقيقية** في جافاسكربت وبايثون (تحقّقنا) — وهي أشيع خطأ يقع فيه المبتدئ العربي. هنا يعمل المصحّح.
3. **NFKC لا يحوّل الأرقام الهندية** (تحقّقنا: `normalize('NFKC','٠١٢٣')` يبقى `٠١٢٣`) — فمن يعتمد على التطبيع وحده يفشل. لذلك نبني خريطة تحويل صريحة (كما يفعل المصحّح).

## 3) اللغة «زيتونة» (Zaytuna)

**المبدأ:** نحو عربي مبني على التعريب المستخدم في التعليم العربي (متغير، دالة، أرجع، طالما) — لا ترجمة حرفية غريبة. الفاصلة المنقوطة اختيارية، والترقيم العربي مقبول.

### 3.1 المعجم الكامل (النموذج الحالي)

| العربية | جافاسكربت | العربية | جافاسكربت |
|---|---|---|---|
| `متغير` | `let` | `إذا` / `وإلا` | `if` / `else` |
| `ثابت` | `const` | `طالما` | `while` |
| `دالة` | `function` | `كرر` | `for` |
| `صنف` | `class` | `لكل … في` | `for … of` |
| `موسع` | `extends` | `كسر` / `استمر` | `break` / `continue` |
| `منشئ` | `constructor` | `أرجع` | `return` |
| `هذا` | `this` | `ارفع` | `throw` |
| `جديد` | `new` | `جرب` / `التقط` / `أخيرًا` | `try` / `catch` / `finally` |
| `ساكن` | `static` | `غير_متزامن` / `انتظر` | `async` / `await` |
| `صحيح` / `باطل` | `true` / `false` | `نوع` | `typeof` |
| `عدم` / `لاشيء` | `null` / `undefined` | `و` / `أو` / `ليس` | `&&` / `\|\|` / `!` |
| `استورد … من` | `import … from` | `مطابق` / `مختلف` | `===` / `!==` |
| `اختر` / `حالة` / `غير_ذلك` | `switch` / `case` / `default` | `انشر` | `...` (بسط/تجميع) |
| `طابق` / `مع` | match (تُترجم إلى `if/else`) | `عام <س>` | معامل نوع عام (يُشطب في JS) |
| `؟` … `:` | الشرط الثلاثي `? :` | `احذف` / `الأصل` | `delete` / `super` |
| `الأصل` | `super` | `احذف` | `delete` |
| `=>` أو `⟶` | دالة سهمية | `(س) => س * 2` | `س ⟶ س * 2` |
| `صدّر` | `export` | `كـ` / `افتراضي` | `as` / `default` |

**ملاحظة قرار:** تُرك اسم `خطأ` **حرًا** (ليس كلمة مفتاحية) كي يُستخدم طبيعيًا: `التقط (خطأ) { … }` — والمنطقي «غير صحيح» يُكتب `باطل`.

### 3.2 الدوال العربية المدمجة

| العربية | تصبح في جافاسكربت |
|---|---|
| `اطبع(…)` | `console.log(…)` |
| `طول(ق)` | `(ق).length` |
| `أضف(ق، عنصر)` | `(ق).push(عنصر)` |
| `رتب(ق)` | `(ق).sort()` |
| `نص(ق)` / `عدد(ق)` / `منطقي(ق)` | `String/Number/Boolean(ق)` |
| `مفاتيح(ك)` / `قيم(ك)` | `Object.keys/values(ك)` |
| `اقسم(ن، ف)` | `(ن).split(ف)` |
| `انضم(ق، ف)` | `(ق).join(ف)` |
| `استبدل(ن، ق، ج)` | `(ن).replace(ق، ج)` |
| `يحتوي(ن، قيمة)` | `(ن).includes(قيمة)` |

### 3.3 ما يُقبل خصيصًا للعربية (وهو ما لا تفعله أي لغة أخرى)

| الميزة | مثال |
|---|---|
| **الأرقام الهندية في الأعداد تُحوَّل تلقائيًا** | `ثابت الأعداد = [١، ٢، ٣]` ← `[1, 2, 3]` (مع ملاحظة تفسيرية) |
| **الترقيم العربي كمرادف** | `،` = `,` و `؛` = `;` |
| **الفاصلة العشرية العربية** | `٣٫٥` ← `3.5` |
| **علامات تنصيص عربية للنصوص** | `اطبع(«مرحبا يا عالم»)` |
| **الفاصلة المنقوطة اختيارية** | نهاية السطر كافية (كما في بايثون) |
| **تعليقات `#` أو `//`** | تُنقل إلى جافاسكربت كما هي |
| **خريطة أسطر** | كل سطر عربي ↔ سطر جافاسكربت (`zaytuna خريطة`) |
| **حروف الوصل/الاتجاه داخل الأسماء = خطأ صريح** | `متغير س\u200B = 1` ← `Z102` |
| **اختيار متعدد عربي** | `اختر (الدرجة) { حالة ٩٠: … غير_ذلك: … }` |
| **بسط/تجميع بالعربية** | `دالة جمع(انشر الأعداد)` و `جمع(انشر [١، ٢، ٣])` |
| **أنماط مطابقة** | `طابق (ق) { مع من ٤ إلى ١٠: … مع [أ، ب]: … غير_ذلك: … }` |
| **شرط ثلاثي عربي** | `ن > ٣ ؟ "كبير" : "صغير"` |
| **أنواع عربية تُشطب** | `دالة هوية عام <س>(قيمة: س): س` |

### 3.4 التشخيصات العربية (مع اقتراح إصلاح)

المُحلِّل يقترح على المستخدم الكلمة المفتاحية الصحيحة رغم التشكيل والأخطاء الإملائية، عبر تطبيع عربي (تشكيل، تطويل، همزات، ياء/تاء):

```text
✖ خطأ Z020 — السطر 8، العمود 1: «طالم» ليست كلمة مفتاحية — هل تقصد «طالما»؟
    ↳ الإصلاح المقترح: اكتب «طالما» بدلًا من «طالم»
```
أمثلة أخرى: `الثابت «س» بلا قيمة` · `رقم ملتصق باسم` · `قوس غير مغلق` · `نص غير مغلق` · `الرقم «5» ملتصق باسم «ص…»`.

### 3.5 نموذج كامل يعمل

```text
# حاسبة زيتونة
دالة صنّف(العدد) {
  إذا (العدد > 10) { أرجع "كبير" }
  وإلا إذا (العدد > 5) { أرجع "متوسط" }
  وإلا { أرجع "صغير" }
}

ثابت الأعداد = [١، ٢، ٣، ٤، ٥]
متغير المجموع = 0
لكل عدد في الأعداد { المجموع += عدد }
اطبع("المجموع = " + المجموع + " — التصنيف: " + صنّف(المجموع))

صنف مركبة {
  منشئ(الاسم، السرعة) { هذا.الاسم = الاسم; هذا.السرعة = السرعة }
  دالة صف() { أرجع هذا.الاسم + " بسرعة " + هذا.السرعة }
}
اطبع(جديد مركبة("صهيل"، ١٢٠).صف())
```

المخرجات الحقيقية موجودة في `DEMO_TRANSCRIPT.md` (القسم 1 و2).

### 3.6 الأنماط — `طابق … مع`

```text
طابق (قيمة) {
  مع ٠:            أرجع "صفر"          # قيمة حرفية
  مع ١، ٢، ٣:      أرجع "صغير"         # بدائل
  مع من ٤ إلى ١٠:  أرجع "متوسط"        # مدى
  مع نوع "string": أرجع "نصّ: " + قيمة # نوع (أو "قائمة" / "كائن")
  مع [أ، ب]:       أرجع أ + ب          # نمط قائمة + ربط أسماء
  مع {اسم، عمر}:   أرجع اسم + عمر      # نمط كائن + ربط أسماء
  مع 99 إذا (صحيح): أرجع "بشرط"        # شرط إضافي على الحالة
  غير_ذلك:         أرجع "غير معروف"    # الحالة الباقية
}
```

الأنماط **تُترجم إلى `if/else` عادية** (بلا مكتبة، وبلا سكر غامض)، وترتيب الحالات مهم: أول نمط مطابق يفوز. الأنماط التي تربط أسماء تُنتج `const` داخل كتلة الحالة نفسها، و«مع» و«إلى» **ليستا كلمتين محجوزتين** (تبقيان صالحتين كأسماء متغيّرات خارج سياق النمط).

### 3.7 الأنواع والأدوية العامة — تُشطب في JS وتبقى في TS

```text
دالة هوية عام <س>(قيمة: س): س { أرجع قيمة }

صنف صندوق عام <س> {
  منشئ(عناصر: قائمة<س>) { هذا.العناصر = عناصر }
  دالة الأول(): س | عدم { أرجع هذا.العناصر[0] }
}

ثابت س: نص = "مرحبا"
ثابت الضاعف = (س: عدد): عدد => س * 2
```

* `zaytuna بناء ملف.zy` → جافاسكربت **بلا أنواع** (شطب كامل، الكود يعمل في أي متصفح/نود).
* `zaytuna بناء ملف.zy --ts` → تايبسكربت بالأنواع والأدوية العامة محفوظة (وفحصه يحتاج `tsc`).
* الأنواع أسماء عربية عادية: `عدد` · `نص` · `قائمة<س>` · `س[]` · `س | عدم` (تُترجم إلى `س | null`).
* **لماذا هكذا؟** لأن اللغة جسر لا جزيرة: الأنواع تعبير عن النية، والشطب يضمن أن المخرج يبقى جافاسكربت مدعومًا في كل مكان.

### 3.8 التصريف الذاتي — زيتونة تكتب زيتونة (يعمل اليوم)

أول جزء حقيقي من الأداة **مكتوب بلغة زيتونة**: `zaytuna/selfhost/اقتراح.zy`
(التطبيع العربي + مسافة ليفنشتاين + قاعدة اقتراح الكلمات المفتاحية). يُترجم بمترجم زيتونة ويُنفَّذ داخل الأداة:

```bash
$ zaytuna اقترح طالم
  ⓘ التنفيذ من selfhost/اقتراح.zy — مكتوب بلغة زيتونة ومُترجَم بمترجمها.
«طالم» ← «طالما»
```

* الاختبارات تقارن هذا التنفيذ (المكتوب بزيتونة) بتنفيذ جافاسكربت على **229 مدخلًا** (كل الكلمات المفتاحية + أخطاء مصنوعة) — **0 اختلافات**.
* هذا هو النموذج المصغّر لهدف «زيتونة تكتب زيتونة» بالكامل: بدل إعادة كتابة المترجم مرة واحدة (الطريق الذي قتل «قلب»)، ننقل أجزاء الأداة جزءًا جزءًا، مع اختبار تطابق يضمن عدم الانحدار.

### 3.9 ما لا تدعمه زيتونة بعد (صراحة)

لا تدعم: الغلق (closures) بمعنى خاص، الوراثة المتعددة، الأنماط المتداخلة العميقة، خيوط المعالجة، ولا مكتبات قياسية عربية خاصة. **منطق القرار:** كل ما هو غير مدعوم يمكن كتابته بجافاسكربت عبر مخرج صريح، لأن اللغة جسر لا جزيرة.

## 4) المصحّح التلقائي (قلب المنتج)

### 4.1 المستويات الثلاثة

| المستوى | ماذا يفعل | أمثلة | سياسة التطبيق |
|---|---|---|---|
| **0 — حتمي وآمن** | يزيل الحروف المخفية (اتجاه/صفر عرض/وسم/تحكّم)، يحوّل الأرقام العربية في الأعداد، يحوّل `، ؛ ٫ ٬`، يحوّل `؟` في الشرط الثلاثي، يزيل التطويل | `let س = ٥، ع = ٣؛` ← `let س = 5, ع = 3;` | يُطبَّق بعد اجتياز التحقق — بلا تدخل |
| **1 — قواعد لغوية** | + إعادة تسمية **متسقة** للأسماء التي تحوي أرقامًا عربية أو تطويلًا (تكرار الاسم نفسه في كل الملف) | `متغير١` ← `متغير1` في كل مواضعها | يُطبَّق مع تقرير لكل تغيير |
| **2 — نموذج لغوي** | إصلاح الأخطاء المنطقية/التركيبية التي لا تغطيها القواعد (مع سياق المستودع ومخرجات المترجم) | خطأ منطقي، حلقة لا تنتهي، واجهة خاطئة | **حلقة تحقق:** يكتب النموذج → يُختبر → إن فشل تُعاد المحاولة برسائل جديدة (حتى 3) → وإن فشلت كلها **لا يُكتب شيء ويُقال ذلك** |

### 4.2 الضمانات (وهي ليست ميزة إضافية، بل شرط الثقة)

1. **التحقق الإلزامي:** لا كتابة بلا `node --check` / `py_compile` / مترجم زيتونة.
2. **لا يُمَسّ النص والتعليق:** الفحص يعرف حدود النصوص والتعليقات (تحقّقنا: `"٥،"` تبقى كما هي داخل الاقتباس).
3. **الإصلاح مُتعادل (Idempotent):** تشغيله مرتين لا يغيّر شيئًا في المرة الثانية.
4. **نسخة احتياطية:** `--write` يكتب `.bak` أولًا.
5. **الشفافية:** كل تغيير مذكور برمزه وموضعه وسببه (`[Z211] سطر 4:9 — عدد عربي «٥» ← «5»`).
6. **ما لا يمكن إصلاحه بأمان يُترك ويُشرح:** `؟` بلا شرط ثلاثي = «نحتاج قرارًا بشريًا»، ولا يُخمَّن.
7. **بلا مدقّق ⇒ بلا كتابة:** إن لم يكن مدقّق اللغة مثبّتًا على الجهاز، يقول ذلك صريحًا ويرفض `--write` (إلا بـ `--no-verify` الصريحة على مسؤولية المستخدم).

### 4.3 مكاننا في السوق (أرقام حقيقية، لا ادّعاءات)

## 5) الحارس الأمني (Trojan Source واليونيكود الخفي)

### 5.1 لماذا هذا ميزة لا تفصيلة

في 2021 كشفت ثغرة **CVE-2021-42574 (Trojan Source)**: أحرف الاتجاه (Bidi) تجعل الكود **يُعرض معكوسًا عمّا ينفّذه المترجم**. رست 1.56 صارت ترفضها، ونقاش المطوّرين خلص إلى أن الحل الصحيح هو **إظهارها للمراجعين** وجعلها قابلة للكشف — لا منع العربية.

**الحجة القوية لزيتونة:** أداة عربية أصلًا تعرف هذه الأحرف وترى الفرق — **فنحن أول من يحوّل خطرًا إلى ميزة**: كاشف يكشف الحرف المخفي ويشرح الهجوم، ويرفض قبوله في الكود (بينما يسمح بـ ZWJ/ZWNJ في النص العربي بتحذير، لأن لها استخدامًا مشروعًا).

## 6) تعدد اللغات (خارطة الدعم)

| اللغة | الفحص | الإصلاح التلقائي | الحالة |
|---|---|---|---|
| اللغة | مدقّق الفحص | الحالة في هذه البيئة |
|---|---|---|
| **جافاسكربت/نود** `.js .mjs .cjs .jsx` | `node --check` (تلقائيًا ESM/CJS) | ✅ مُتحقَّق منه |
| **بايثون** `.py` | `py_compile` | ✅ مُتحقَّق منه |
| **زيتونة** `.zy` | مترجم زيتونة نفسه | ✅ مُتحقَّق منه |
| **سي** `.c .h` | `gcc -fsyntax-only` (أو cc/clang) | ✅ مُتحقَّق منه |
| **سي++** `.cpp .cc .cxx .hpp` | `g++ -fsyntax-only` | ✅ مُتحقَّق منه |
| **شل** `.sh .bash .zsh` | `bash -n` | ✅ مُتحقَّق منه |
| **بيرل** `.pl .pm` | `perl -c` | ✅ مُتحقَّق منه |
| **تايبسكربت** `.ts .tsx` | `tsc --noEmit` (أخطاء البنية فقط) | جاهز — المدقّق غير مثبّت هنا |
| **جافا** `.java` | `javac` (مع إعادة تسمية الملف للصنف العام) | جاهز — يحتاج JDK |
| **جو** `.go` | `gofmt -e` (بحث تلقائي داخل GOROOT) | جاهز — يحتاج Go |
| **رست** `.rs` | `rustc --emit=metadata` | جاهز — يحتاج rustc |
| **بي إتش بي** `.php` | `php -l` | جاهز — يحتاج PHP |
| **روبي** `.rb` | `ruby -c` | جاهز — يحتاج Ruby |
| **سي شارب** `.cs` | `dotnet build` | لا تحقق على ملف منفرد (يحتاج مشروعًا) |
| **سويفت** `.swift` / **كوتلن** `.kt` | `swiftc -parse` / `kotlinc` | جاهز — يحتاج الأدوات |
| **SQL** `.sql` | لا نُشغّل SQL للتحقق (أمان) | فحوص Unicode والترقيم فقط |

**الأهم:** عند غياب المدقّق لا نُعلن نجاحًا — نقول «لم أتحقق» ونذكر أمر التثبيت، **ونرفض الكتابة** (`إصلاح --write` يفشل) إلا بطلب صريح `--no-verify`.

**المعمارية:** الواجهة الموحّدة `src/index.js` تعزل كل لغة في «مشغّل مدقّق» واحد + جدول رسائل مترجمة. إضافة لغة = ملف واحد + جدول ترجمة رسائل المترجم — لا إعادة كتابة.

**أهم قرار:** **لا ندّعي دعم لغة لا نتحقق منها.** لو لم يوجد مدقّق (مثل TypeScript هنا)، نقول ذلك صراحةً بدل تمرير «نجاح» كاذب.

## 7) المنتج: كيف يبدو في الجيب؟

**الشاشة 1 — المحرر العربي:** لوحة مفاتيح برمجية عربية (رموز `{}؛` في متناول الإصبع)، تلوين، إكمال بالكلمات العربية، وتدقيق فوري في الهامش.

**الشاشة 2 — إصلاح بضغطة:** «افحص ملفي» ← قائمة «ما يمكن إصلاحه الآن» («٩ مشاكل جاهزة للإصلاح») ← زر واحد ← عرض الفرق ← ثم **النتيجة**: «تم — الملف سليم الآن (تحقق node)». وإن لم يمكن التحقق: «لم نكتب شيئًا — راجع يدويًا».

**الشاشة 3 — التقرير العائلي:** لوحة لكل مشروع: كم خطأ عربيًا؟ كم حرف مخفيًا؟ (وهنا يظهر أنه **حارس أمني** لا مصحّح أخطاء إملائية فقط) — مفيد أيضًا لمديري الفرق.

**الشاشة 4 — مدرّب:** «تعلّم زيتونة في 20 درسًا» — والدرس الأخير: اقرأ كودك القديم بلغة عربية. (هذه هي بوابة التبنّي الحقيقية: الجيل الجديد يتعلم بها، والقدامى تستفيد بأدواتها).

## 11) لماذا أنت تحديدًا؟

1. **عربي + تقني:** تستطيع أن تُناقش «هل الصحيح `أرجع` أم `أعد`؟» و«لماذا `باطل` أنسب من `خطأ`؟» — هذا ما لا يفعله أي منافس غربي.
2. **المشروع قائم على منتج مزدوج:** لا يحتاج شركة (14 لغة) كي يبدأ؛ الأدوات (مصحّح + حارس) تعمل وحدها وتجلب مستخدمين، واللغة هي البانر.
3. **قيمة تراكمية:** كل لغة تُضاف × كل ميزة = سطح منتج لا يستطيع منافس بناه بالإنجليزية تحويله إلى عربي بسرعة.
